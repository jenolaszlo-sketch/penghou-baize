# Model tool-call compatibility

This is a living record of models tested with Solo's `emit_files` workflow. Add a row whenever a model or API style is tested.

The current test asks the model to emit a complete, compilable .NET solution containing a solution file, an application project, a test project, source files, and tests. Results are empirical: advertised tool support does not guarantee that a small model can complete this particular task.

## How failures are handled

Solo treats these as different failure classes:

1. **No native tool call:** inspect assistant content for a pseudo tool call.
2. **Malformed JSON:** apply focused text repairs, then schema-guided tolerant syntax-tree recovery.
3. **Valid JSON with the wrong shape:** validate it against the tool schema and reject it with a useful explanation.
4. **Missing project artifacts:** write the files that were returned, but report the missing solution or project files.
5. **Missing content, timeout, or empty response:** report model/provider diagnostics. Repair cannot recover information the model never returned.

When comparing models, record native tool-call success separately from JSON repair success and generated-project correctness.
